# 场景：X 深度图文长文

- 开头约 280 字提供能被核对的实测结果、事实、产品问题、个人真实经历；避免空泛“震惊”。
- 如果用户给了 GitHub 仓库，先检查 README、LICENSE、部署说明、实际功能和在线站点可用性；未经验证则标待核实。
- 内容组织：读者问题 → 价值与实测证据 → 可复现操作步骤 → 常见错误及限制 → 总结与下一动作。
- 重要结论配来源和必要截图占位要求。无实际截图不能虚构，禁止伪造播放/收益/性能结果。
- 使用用户真实案例；对案例库中的客户信息脱敏，明确区分已交付结果和待验证假设。
- 图片用“建议截图：某页面/命令结果”描述，除非已有真实截图可引用。
- 代码和命令可复制；平台早期可见区域先写结果。把有效链接置于合适位置。
